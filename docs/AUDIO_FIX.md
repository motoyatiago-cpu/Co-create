# 声音启动与音量修复

本轮按用户“修复音效问题，放大到合适程度后上线”的要求修改两处体验。

- 故事界面不再把保存的声音偏好直接当作已播放；首次显示“点击开声”，实际音频上下文运行后才显示“声音已开”。保留上次偏好，刷新后通过首次有效交互恢复播放，点击声音按钮不会被自动恢复逻辑反向切换。
- 启动失败或没有音频API时，开关保持关闭。使用请求序号处理并发启停，避免过期启动回调重新打开已关闭的声音。
- 故事环境声分支从0.055调整到0.6，淡入1.2秒，总线淡入0.8秒并增加动态峰值控制。与之前实测约-51dBFS相比，目前稳态约-28dBFS，保留柔和淡入和静音淡出。
- 剪片保留原合成音源，在原压缩器后统一加1.15倍增益及峰值控制，再分流到扬声器和导出音轨。扬声器默认由0.78调整到1，理论播放提升约3.4dB；静音仍到0，用户音量接口保留。
- 没有修改操作系统音量、放宽浏览器自动播放权限或替换产品视觉。

## 实际验证

生产构建通过；完整22项浏览器测试通过（桌面11项、触屏模拟11项，约1.1分钟）。新增声音检查涵盖：

1. 故事开启后非零输出、刷新后状态准确、交互恢复、静音、再次开启及无API降级。
2. 剪片全部6种情绪合成音源均非零输出，静音/恢复有效，导出流存在live音频轨道。
3. 最终输出采样无幅值触顶：测试要求峰值小于0.95，实际样本最高约0.42；故事稳态RMS约0.0397（-28dBFS），峰值约0.095。
4. 既有32人、5位联系人、45人容量、导航、独立体验、减少动画和布局检查继续通过。

测量使用审计会话中串接最终输出的AnalyserNode，没有调高测试探针增益。数字电平检查不能替代不同实体音箱的听感；未宣称覆盖任意上传音源的全部瞬态或完成导出文件的逐一试听。声音不依赖外部mp3，默认仍为Web Audio实时合成。

故事体验只提供编译后的单文件HTML，本轮对音频及其状态逻辑作有边界的补丁；没有重新生成或替换整份体验。源码包优先的其他视觉保持原样。
